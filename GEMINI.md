# GEMINI.md - Project Context & AI Guidelines

## 📌 Project Overview
**excelreaderwasm** is a high-performance, client-side spreadsheet reader and chunk parser powered by **Rust** and **WebAssembly (WASM)**. It allows web applications to parse large spreadsheet files (`.xlsx`, `.xls`, `.ods`, `.csv`) directly in the browser or Node.js environment with minimal memory footprint, row-chunk streaming, header validation, field mapping, and built-in **CRC32 data integrity & server completeness verification**.

---

## 🛠️ Technology Stack
- **Core Engine (Rust)**:
  - `calamine` (0.26, `features = ["dates"]`): Fast spreadsheet reader supporting multiple formats.
  - `wasm-bindgen` (0.2): Bridge between Rust and JavaScript.
  - `crc32fast` (1.4): Hardware-accelerated CRC32 calculation for chunks and full dataset.
  - `serde` & `serde_json`: Serialization and structured JSON interoperability.
  - `chrono` (0.4): Excel date/time formatting.
- **JavaScript & Tooling**:
  - ES Modules (`"type": "module"`).
  - `wasm-pack`: WASM compilation targetting the web (`--target web --out-dir pkg`).
  - `vite` (v6+): Local development server and interactive demo bundler.
  - `TypeScript`: Type definitions provided via `index.d.ts`.
  - `xlsx` (DevDependency): Used for generating mock Excel data in automated tests.

## 🧱 Architecture & Key Concepts

### 1. Data Processing Pipeline
1. **File Ingestion**: Accepts `File`, `Blob`, `ArrayBuffer`, or `Uint8Array`.
2. **Rust/WASM Parsing (`ExcelReader`)**:
   - Header validation against pipe-delimited (`"No|Nama|Alamat"`), comma-delimited, or JSON array strings.
   - Column mapping (`{"id": "No", "address": "Alamat"}`) to transform spreadsheet rows into structured JSON objects.
   - Row chunking into specified batch sizes (e.g., 1000 rows/chunk).
   - Computing individual chunk CRC32 checksums and a total session CRC32 checksum.
3. **Upload & Streaming Loop (`onUploading` / `onProgress`)**:
   - Asynchronously streams each chunk with full metadata (`ChunkMeta`: uploadId, chunkIndex, startRow, endRow, checksum).
4. **Server Completeness Verification (`verifyServer` / `verifyUploadCompleteness`)**:
   - Reconciles total expected rows & chunks against backend staging status to guarantee zero data loss before final commit.

### 2. Main API Interfaces (`index.js` / `index.d.ts`)
- **`uploadSpreadsheet(fileOrOptions, validHeader, mappingHeader, rowChunk, options)`**:
  - Flexible signature: supports both positional arguments and a single configuration object.
  - Returns `Promise<UploadResult>`.
- **`SpreadsheetUploader`**:
  - Event-driven class extending `EventTarget`.
  - Emits: `start`, `uploading`, `progress`, `complete`, `error`.
- **`initWasm(wasmSource)`**:
  - Lazy initialization of WASM module with optional custom source/URL.
- **`verifyUploadCompleteness(manifest, serverStatus)`**:
  - Utility helper to validate if server received all chunks without discrepancies.
- **`ExcelReader` / `parseSpreadsheetDirect`**:
  - Low-level WASM bindings exported directly from `pkg/`.

## 📝 Coding & Contribution Guidelines for AI

1. **WASM & Memory Safety**:
   - Always call `reader.free()` inside a `finally` block when instantiating `ExcelReader` directly in JavaScript to prevent WASM memory leaks.
   - Ensure Rust code maintains memory safety and properly handles invalid spreadsheet encodings or corrupted files with descriptive errors (`JsValue`).

2. **API & Type Synchronization**:
   - Whenever changes are made to `src/lib.rs` structs or `index.js` exports/options, **always update `index.d.ts`** to keep TypeScript declarations in sync.
   - Maintain dual invocation support for `uploadSpreadsheet` (both positional parameters and option object).

3. **Date & Number Handling**:
   - Excel dates must be formatted consistently (`YYYY-MM-DD` or `YYYY-MM-DD HH:mm:ss`).
   - Floats representing integer values should be normalized to integer numbers where appropriate.

4. **Checksums & Integrity**:
   - Use `crc32fast` for standard CRC32 checksums in hexadecimal format (`%08X`).
   - Preserve chunk manifest ordering (`chunk_index` 1-based indexing).

5. **Testing Requirements**:
   - Verify any parser or chunking logic changes by running `npm test`.
   - If adding new features, add corresponding test cases to `test/` or interactive UI controls in `demo/`.
